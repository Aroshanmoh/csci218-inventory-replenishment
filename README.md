# Inventory Replenishment as Constraint Optimisation

CSCI218 (Foundations of AI) group project. Given each product's stock, demand,
cost, MOQ, order multiple, lead time, safety stock, max stock and priority, plus
a purchasing budget and warehouse capacity, the system recommends **which
products to reorder, how much, and which to prioritise when resources are short**.

The problem is modelled as a **Constraint Optimisation Problem** and solved two ways:

- **Our own CSP solver** (`src/csp_solver.py`): backtracking, forward checking,
  branch and bound with an admissible relaxation bound, dominance pruning, and
  variable/value ordering.
- **HiGHS MILP solver** (`src/optimizer.py`, via PuLP): the same model, which
  scales to hundreds of SKUs.

Both are compared with two traditional baselines (`src/baseline.py`): a
reorder-point policy and a fair greedy policy, all scored by one shared
evaluation function (`src/evaluation.py`).

Python 3.13.

```bash
python3 -m venv .venv

```

## Run

| What | Command |
|---|---|
| Interactive app | `python -m streamlit run app.py` (tick "Use bundled sample data", then **Run AI Optimizer**) |
| Compare all methods on the sample data | `python main.py` |
| ...plus six what-if scenarios | `python main.py --scenarios` |
| Tests (261) | `python -m pytest` |
| Experiments 1–3: size, budget, capacity (~2 min) | `python experiments/run_experiments.py` |
| Experiments 4–6: solver vs HiGHS, ablation, weight sensitivity (~2 min) | `python experiments/run_solver_study.py` |
| Rebuild report tables / figures | `python experiments/make_tables.py` / `python experiments/make_figures.py` |

Add `--quick` to either experiment script for a fast smoke run, and
`--no-save` to `main.py` to print without writing files.

## Reproducibility

- Every random instance is generated by `src/instances.py` from a recorded
  seed (`seed` column in every results CSV), so any row can be regenerated.
- All results used in the report are committed in `results/`; tables in
  `results/tables.md` and figures in `results/figures/` are generated from those
  CSVs, never typed by hand.

## Project structure

```

src/
  csp_solver.py            Our backtracking + forward checking + branch-and-bound solver
  optimizer.py             MILP model solved with HiGHS (lexicographic objective)
  baseline.py              Reorder-point and greedy baselines
  evaluation.py            Shared evaluation applied to every plan
  scenarios.py             Six single-factor what-if scenarios
  instances.py             Seeded random instance generator
  data_loader.py, rules.py Input validation and derived metrics
experiments/               Experiment, table and figure scripts
results/                   Committed CSVs, tables.md, figures/
tests/                     pytest suite (incl. brute-force optimality oracle)
docs/REPORT_SKELETON.md    Report skeleton in the required structure, with results
data/                      Sample inventory and company settings
```

## Model assumptions

- Demand and costs are deterministic within a scenario.
- Incoming stock arrives within the planning horizon (no arrival dates in the data).
- Orders whose lead time exceeds the horizon cannot help the current plan, so
  they are not funded. The SKU is instead flagged **"ORDER NOW FOR NEXT CYCLE"**
  with a suggested lot and its cost.
- The shortage weight priority × (1 + lead time / horizon) is a modelling
  choice; `urgency_mode="priority"` switches to priority only (see Experiment 6).
